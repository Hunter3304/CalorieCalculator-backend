# Iteration Plans

Create one Markdown plan before implementation begins for every feature, fix, deployment, release, or documentation iteration.

Use this filename format:

```text
yyyy-MM-dd-short-iteration-name.md
```

Each plan should record:

1. Requested outcome and background.
2. Scope and affected repositories.
3. Product rules, assumptions, and exclusions.
4. Planned implementation steps.
5. Test and verification strategy.
6. Deployment, release, rollback, and data-safety considerations when applicable.
7. Related GitHub Issues, branches, Pull Requests, and Projects.
8. Status and any changes from the original plan.

When an iteration is complete, create the corresponding feedback record under `../iterations/`, then update `../README.md` and `../HANDOFF.md`. Mirror shared documentation changes in both repositories.
